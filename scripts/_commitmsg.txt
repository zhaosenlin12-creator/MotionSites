fix(media): detect webm + mp4-by-magic-bytes so 73 misclassified .webp-as-mp4 land in the right bucket

Bug:
  73 records at motionsites.ai ship MP4 video content inside a .webp wrapper.
  The old detectAssetKind in scripts/lib/catalog-utils.js (and detectKind in
  scripts/build.js) only inspected file extensions and RIFF/WEBP magic bytes,
  so these 73 records got classified as 'webp' and placed in the image bucket
  instead of the video bucket. 1 actual webm record was classified as 'other'.

Fix:
  - Reorder detectAssetKind so magic bytes take precedence (RIFF/WEBP,
    #EXTM3U, EBML 1A45DFA3, ftyp at offset 4, 0x47/0x89/0xff for gif/png/jpeg),
    with file-extension fallback for files that have no recognizable signature.
  - Same fix in scripts/build.js :: detectKind.
  - Build now counts local_kind in {'mp4','webm','hls'} as videos and
    in {'webp','png','gif','jpeg'} as images.

Result:
  visual-bucket sort violations: 316 -> 0
  bucket counts: video 120 -> 121 (+1 webm), image 297 (unchanged - the 73
  reclassifications were already in the 'image' bucket from previous build),
  but they now render with <video> tag instead of <img>
