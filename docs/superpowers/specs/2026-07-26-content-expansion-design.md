# MotionSites Prompts 内容扩充设计

## 目标

在不降低现有页面质感、预览质量和交互完整性的前提下，补齐能够从公开 GitHub 仓库确认的完整提示词，并新增一个与 MotionSites 主库明确分区的“社区精选”内容集合。

## 内容边界

- 保留现有 MotionSites 主库条目、图片和视频，不对优质素材进行有损压缩或无关替换。
- GitHub 已公开仓库可作为候选来源；每个来源记录仓库、作者、许可证、原始文件路径和链接。
- 原始 MotionSites 条目仅在找到可验证的完整原文时补齐，不以模型生成内容冒充原文。
- 非 MotionSites 来源进入“社区精选”，不与原始库混标。
- 没有真实效果素材的条目使用统一概念卡，不使用无关截图冒充实际预览。

## 数据结构

每条新增或补齐记录至少包含：

- 稳定 ID、标题、分类和内容类型。
- 完整提示词正文与正文完整度状态。
- 来源类型：`motionsites` 或 `community`。
- 来源仓库、作者、许可证、原始路径、原始 URL 和导入日期。
- 可选的本地预览资源；不存在时明确使用概念预览。

## 导入与去重

1. 解析候选仓库中的 Markdown、JSON 或 TypeScript 数据。
2. 通过规范化 ID、标题和正文哈希匹配现有记录。
3. 优先补齐现有空正文或短正文记录。
4. 新内容通过质量门槛后进入社区精选。
5. 重复正文只保留来源最清晰、元数据最完整的一条。

## 质量门槛

完整提示词应提供足够可执行的信息，至少覆盖目标与场景，并在视觉规范、页面结构、交互/动效、响应式或实现约束中覆盖多个方面。以下内容不进入完整目录：

- 只有标题、标签或宣传文案的元数据条目。
- 内容明显截断、占位或依赖付费页面才能查看的条目。
- 与已有正文高度重复且没有新增价值的条目。
- 来源不清晰或原始链接无法确认的内容。

## 仓库与资源策略

- `sources/` 仅用于本地研究，不纳入公开仓库。
- 公开仓库只保留来源清单、可重复执行的导入脚本、标准化数据和必要预览资源。
- 不新增超过托管平台限制的大文件；保留现有构建脚本的 24 MiB 预览安全阈值。
- README 展示最新条目数量、完整正文数量、内容分区、来源原则和在线地址。

## 页面表现

- 主库与社区精选可独立筛选，并在卡片和详情中显示简洁的来源类型。
- 详情页对完整原文提供可靠复制反馈；不完整条目只展示已验证元数据，不显示空白正文。
- 现有中英文界面、搜索、分类、视频预览和响应式布局保持可用。

## 验收标准

- 数据审计无空字符串被标记为完整提示词。
- 新增内容无重复 ID，正文重复可解释且来源可追溯。
- 所有本地图片、视频和缩略图路径存在，页面无资源 404。
- 构建成功，生成页面中的统计数字与数据文件一致。
- 浏览器检查搜索、筛选、详情打开、复制、中英文切换和视频播放。
- 控制台无新增错误，静态站可在 Cloudflare Pages 正常访问。
- 工作在独立分支完成，通过本地验证后再合并和部署。
