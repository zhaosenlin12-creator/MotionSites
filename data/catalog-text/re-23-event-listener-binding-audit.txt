Audit how one control is actually wired before reproducing its feel. Select a single node by CSS selector and list the directly registered listener types with their flags: capture or bubble, passive, once, plus the callback coordinates as a zero-based line with a UTF-16 column in the named resource and the source text digest, so the same handler stays identifiable across reloads. Inspect the node and never dispatch an event, and expect three blind spots: listeners on delegated ancestors, listeners inside closed shadow roots, and framework registries that attach nothing per node. When a click works but the node lists nothing, walk the ancestor chain and record the delegation depth as a number rather than a shrug. Re-inspect after each state change, because hover, focus and open states often add listeners later: capture the binding set cold, after hover, after click and after Escape, then diff the four sets and show which listeners exist only after a state change. Keyboard coverage matters as much as pointer, so check keydown and keyup on the control and on document, and note where a passive flag rules out preventDefault for a custom wheel or touch effect. Report unknown where a call site has no script identity instead of guessing the handler. Rebuild stack: one listener table per control, consumed as the wiring spec. Acceptance: each row has type, phase, passive flag and a source location, delegation is either proven with a depth or marked unknown, the four state snapshots are diffed, the audit dispatches no event itself, and post-interaction bindings are listed apart from startup bindings.
