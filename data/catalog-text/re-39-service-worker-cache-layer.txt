Find out whether a worker sits between the page and the network before trusting any capture. Record the service worker policy the scenario environment reported, then on an attached browser check the registrations list and the controller, and read the worker script URL with its scope. Enumerate what it stores by walking Cache Storage: cache names, entry counts and total bytes per cache, without reading bodies that belong to another origin. Characterise the strategy with two loads, the first with the worker active and storage cleared, the second with the same worker and warm caches, comparing which requests reached the network, which were answered from cache, the response time for both, and whether an older build was served. Look for the stale signature: a hashed asset in the document that disagrees with the current reference list, a navigation answered offline from an old shell, a versioned cache that was never deleted. Reproduce first-load behaviour with registration blocked and storage cleared so the rebuild is measured against the origin rather than somebody's cache. Capture only public responses and label any storage you could not read as unknown, tagging each entry observed or inferred. Rebuild stack: a versioned precache keyed by build id, network-first for documents, stale-while-revalidate only for images, and an activate step that deletes superseded caches. Acceptance: the inventory names script, scope and every cache with entry count, the two loads are compared, the stale signature is found or explicitly absent, and an offline reload serves the current build id.
