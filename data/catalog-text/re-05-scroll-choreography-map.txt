Goal: convert a scroll-driven section into a numeric scroll map. Step the page from 0 to document height in 200px increments, waiting two animation frames between steps, and record for each probe element its boundingClientRect.top, computed position (sticky or fixed), transform matrix, opacity and any custom property the site updates. Derive the exact scroll offsets where behaviour changes: pin start and end, reveal thresholds, and the point where a sticky element releases. Treat the range as progress = (scrollY - start) / (end - start) and sample animated values at 0, 0.25, 0.5, 0.75 and 1. If the site uses CSS scroll-driven animations, read animation-timeline support and the ViewTimeline or TimelineRange names from computed style; if it uses GSAP ScrollTrigger, capture trigger, start, end, scrub and pin from ScrollTrigger.getAll(); if it uses IntersectionObserver reveals, hook the constructor before navigation with addInitScript and log thresholds and rootMargin. Detect scroll hijacking wrappers (Lenis, Locomotive, ScrollSmoother) because they change the scrollY mapping. Rebuild stack: GSAP ScrollTrigger with scrub for pinned sequences, or native CSS scroll-timeline with an @supports fallback, and content that still reads with JavaScript disabled. Acceptance: clone pin start and end land within 2 percent of page height at 1440x900, progress-driven values match at all five sample points, the section stays keyboard and screen-reader navigable, and reduced motion collapses it to a static layout.
