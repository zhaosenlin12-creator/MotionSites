Build a state coverage matrix before styling anything, so the missing cells become the plan. Put parts down the left and states across the top, one cell per pair, each cell marked built, borrowed or missing. List the parts from the reference section: inline link, icon button, primary action, secondary action, segmented control, dropdown, text field, checkbox, card, tab, accordion row, carousel control, toast and one media hover. Across the top put seven states: rest, hover, focus-visible, active or open, disabled, loading, error. Fill what exists, then mark the remainder missing and count them; that number is the schedule, not an opinion. Write each cell's visible difference in one clause, for example hover on the secondary action raises its surface one step and moves nothing, while focus draws a 1 px hairline in the accent ink plus a 3 px halo. Build in dependency order: surfaces first, then hover and focus, then active and open, then disabled, then loading and error, since loading needs a reserved layout or the page jumps the moment a spinner appears. Acceptance: every part has all seven states either built or deferred with a written reason; a scripted pass sets each state by attribute and screenshots it; only open and error change layout height, each by a recorded amount; the matrix ends with zero unexplained empty cells.
