Write the content model before any layout exists, so real copy drives the grid instead of placeholder text. Produce one table, one row per string and asset the section needs: key, role, English text, measured character count, maximum allowed characters, minimum, may wrap, is editable, and which element renders it. Cover headline, eyebrow, subhead, action labels, feature titles, feature bodies, captions, table headers, empty copy, error copy, alt text and the logo slot. Take the English length by counting characters, not words, and set the maximum at 130 percent of it rounded up to the nearest 5. Anything under 40 characters must not wrap; body copy wraps between 62 and 68 characters per line. Then write the constraints that follow from the numbers: the headline block holds a fixed two-line height so a longer string pushes nothing below it, card titles clamp at three lines, buttons take a 40 px height with 16 px side padding and truncate only past their own maximum. Add an overflow fixture per key: the longest allowed string, one string with an emoji, and one unbroken 40-character word. Acceptance: every visible string traces to a table row; injecting each overflow fixture changes no pixel outside its own block; a scan finds no key over its maximum; a second developer rebuilds the section from the table without reopening the reference.
