Write the acceptance self-test harness before the last pass, so fixes are driven by measurement. Structure it as a flat list of claims, each one sentence, each judged by a check that returns passed, failed or unmeasured with a detail string. First build the harness: a script that builds the project, serves the output on loopback, captures each page at the configured widths, and writes a JSON report per round. Then add claims in four groups. Visual: per width likeness score plus page height delta. Structural: landmarks, heading text present, section order, missing parts. Behavioural: menus and modals open on click and on Enter, focus returns to the trigger, no console errors the original does not also log, no failing request the original does not also have. Content: no missing headings, no dropped words. Then add the rule that matters: a check that could not measure something reports unmeasured and blocks a pass, so silence is never rounded up to success. Acceptance self-tests: the harness reports each claim with its evidence, an overall score and an explicit unknowns list; two consecutive runs give the same result; a deliberately broken build fails the right claim and no other; the loop is capped at three rounds and stops when a round changes nothing.
