Build a reusable scramble-reveal component. Given a target string, render it uppercase in a monospace face at 0.08em tracking, color #e6ffe6 on #0a0a0a, and reserve the final width so nothing reflows. Trigger on first entry into view (IntersectionObserver, threshold 0.4) and on hover. Run a 950ms reveal where every character first shows a random glyph from ABCDEFGHJKLMNPQRSTUVWXYZ0123456789#$%& and locks to the real character when a left-to-right front passes its index. Tick roughly 32ms with requestAnimationFrame, but derive progress from elapsed time so slow frames do not stretch the duration; stagger 12ms between neighbours and keep every fourth space permanent. Hover re-run: scramble only the hovered word for 450ms, never the whole line. Mark the animated span aria-hidden, expose the true string in aria-label, and respect prefers-reduced-motion by painting the final string immediately. Add a 1px #39ff14 underline that draws in over 300ms after the reveal, and a small mono label such as 0x1F above the block. Acceptance: final state is exactly the target string with no width jump because width is measured once, CPU stays under 3% when idle, scroll-back re-triggers at most once per element, and screen readers announce the label once with no glyph noise.
