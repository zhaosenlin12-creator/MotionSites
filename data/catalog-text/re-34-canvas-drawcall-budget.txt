Measure what a canvas hero costs per frame before deciding how to rebuild it. Attach passively, hook the WebGL and WebGL2 draw functions through an init script so the counters exist before the scene compiles, and sample for a fixed 3 second window with the pointer resting still. Record per frame: drawArrays, drawElements and instanced call counts, texture and buffer upload bytes, program switches, the renderer string from the debug renderer info extension, canvas width and height in device pixels against CSS size, devicePixelRatio, the requestAnimationFrame interval, and the longest frame in the window. Turn that into a budget: a 16.7 ms frame at 60 Hz leaves roughly 8 ms for the scene after style, layout and composite, so state the target as calls per frame, uploads per second and megapixels per frame. Note whether the page clamps devicePixelRatio at 2, renders at half resolution and upscales, and pauses the loop on visibility or intersection changes. Where a counter cannot be observed, say so instead of estimating silently. Rebuild stack: instanced geometry, one atlas texture, a clamped pixel ratio, and a loop that stops when the canvas leaves the viewport. Acceptance: the counter table covers at least 180 frames, the budget states calls, uploads and megapixels, the clone holds under 8 ms of frame time at 1440x900, and every unobserved metric is listed as unknown.
