Rebuild a dense data table from its type ramp instead of from a comfortable default. Derive the row height: body text at 14 px with a 1.45 line height gives 20 px of text, plus 12 px top and bottom, so the compact row is 44 px; set a roomy row at 56 px and switch between them with one density token rather than a class per table. Align by data type: text left, numbers and currency right with tabular figures, dates right, status pills left, row actions right and never in the first column. Keep the header sticky with a 1 px separator and a surface one step lighter; choose separators or zebra striping, not both, and if zebra, cap the alternating fill at 4 percent alpha so scanning still works. Size numeric columns from the widest value, not from the header text, and let the flexible text column absorb the remaining width. Then the phone rule: below 768 px the table becomes cards, one card per row with a label and value pair per cell, secondary cells behind a disclosure, and the primary identifier as the card title. Acceptance: row height matches the density token at both settings; the header stays visible after scrolling 600 px; numeric columns stay right aligned with tabular figures at every width; no header wraps to two lines at 1440 px; the 390 px card view keeps every primary value; no tested width scrolls horizontally.
