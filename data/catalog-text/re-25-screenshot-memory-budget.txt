Compare long pages without letting the comparison decide your memory ceiling. Measure document height first, then choose a tile height from it instead of taking one full-page shot: a 1440 by 20000 page at four bytes per pixel is about 115 MB per image before two decoded buffers and the RGB to RGBA expansion are counted, while a 1440 by 1600 tile pair stays near 27 MB. Admit each pair against a working-memory budget of 256 MiB and treat a header-valid image that exceeds it as a resource constraint carrying the estimate and the maximum, not as a corrupt file. Tile both captures at identical offsets with a one-pixel overlap guard so a seam is not reported as a difference, hash each tile, compare only tiles whose digests differ, and stream every verdict to disk as it is produced so the run never holds more than one pair in memory. Keep the page at a fixed scroll position while a tile is captured and record the scroll offset beside the tile index, so a re-run cannot compare two different crops. Compare by content digest rather than raw bytes, and count the pixels outside text antialiasing before calling a tile matched: one percent of a tile is an honest threshold, zero is not. Rebuild stack: a tiling script plus a per-tile report file. Acceptance: peak memory stays under the stated budget on a 20000 pixel page, every tile carries index, scroll offset and digest, uncompared or failed tiles are listed instead of silently passing, and the final difference figure is computed from tiles alone.
