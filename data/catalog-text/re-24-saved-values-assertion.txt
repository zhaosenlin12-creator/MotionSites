Keep a rebuild honest with a small, re-runnable assertion set. Choose eight to twelve numbers a viewer would notice: a stagger interval, a hero duration, a pin range in pixels, a headline size at two widths, a card radius, a grid gap, a settled opacity and a colour. Capture each from the reference by reading a json_pointer out of a matching 2xx JSON response or a computed style, saving it under a stable name with its unit written beside it; a pointer that names no string or number must fail the step instead of storing a blank. Treat re-observable as a test: the same step replayed on a second reference run and then against the rebuild has to yield the same number, so a value typed in by hand does not qualify. Run the loop with two tolerance classes: exact for counts and enumerations, plus or minus one frame for durations and plus or minus one pixel for sizes, and record which class each row uses. Diff the rebuild against the reference row by row and keep the failures: a duration that misses by 40ms is a finding, not a rounding choice. Report every row the loop cannot observe, such as a value behind a login or set only under one device profile, as unknown with its reason. Rebuild stack: an assertions JSON plus a runner printing pass, fail or unknown per row. Acceptance: every row has a name, unit, value, tolerance class and provenance, the same step produces the row on both sides, no row is hand-entered, failures are reported rather than smoothed, and unobservable rows are marked unknown.
