Derive one control size scale and let every control on the page come from it. Pick four heights, 24, 32, 40 and 48 px, and bind each height to a label size, a side padding and an icon box so a row of mixed controls lines up without per-page fixes: 24 px for toolbar and table rows with 12 px padding and a 14 px icon, 32 px as the default with 13 px padding and a 16 px icon, 40 px for full-width fields and a screen's main switch, 48 px kept for the single primary action with 20 px padding and a 20 px icon. Declare them as control-sm, control-md, control-lg and control-xl, each exposing --control-height, --control-pad-x, --control-font and --control-icon, so a component reads one token and inherits all four values. Ban bare numbers in component CSS and enforce it with a test that walks component sources for px literals outside the token file; allow only computed sizes such as calc(var(--control-height) - 2px) for inner content. Render the scale as one page: each control at each size, in rest, hover, focus-visible, pressed and disabled, with its measured box printed beside it. Then verify the rule by swapping a medium button to large and confirming height, padding, label and icon move together and nothing else changes. Acceptance: two controls of the same size measure the same outer height within 1 px; no component file holds a literal height or padding; the label and focus ring stay optically centred at all four sizes; the rendered heights are exactly 24, 32, 40 and 48 px at 100 percent zoom.
