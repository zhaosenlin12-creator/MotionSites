Write the scenario file before a browser is opened, and treat it as the run contract rather than a note. Declare the browser mode (launch with an absolute executable path), the start URL, a viewport of 1440x900, and the action list; device scale and reduced-motion emulation are separate explicit fields. Every step carries a unique step_id and its own timeout_ms around 10000, and uses one of the fixed kinds: goto, wait_for, click, hover, press, scroll, wait_for_timeout, evaluate, screenshot. Readiness is a page-owned marker such as #hero[data-state='ready'] in state visible, never a fixed 500ms sleep and never a container that was already on screen before the step. Save the twelve numbers you intend to prove with save-value steps that read json_pointer paths out of a matching 2xx response, and make each one re-observable: the same step, replayed on a second run and then against the rebuild, must produce the same value. Validation runs before capture and refuses duplicate step ids, a saved name no earlier step binds, an undeclared origin on a request step, unknown fields, and a missing terminal step. Reject any scenario whose waits a reader cannot bound. Rebuild stack: a checked-in scenario JSON plus a validator wired into CI. Acceptance: validation exits clean before the first capture, every step has a timeout and a unique id, the readiness marker is page-owned rather than a sleep, a third run reproduces each saved value, and any state the scenario cannot reach is written down as unknown with its reason.
