Rebuild a hint graph deliberately instead of hoping the browser guesses well. Load the reference at 1440x900 with cache disabled and a fresh profile, and record every request with its initiator, priority and start time. From the document head extract preload, preconnect, dns-prefetch, modulepreload and prefetch links with their as, type, crossorigin and media values, plus any fetchpriority attribute on images, scripts and frames. Identify, from the observed start times, the four assets that begin first and what pulled each one: a preload link, an early script, the parser, or a stylesheet's font rule. Price each hint: a preconnect to an origin the page never touches, a crossorigin mismatch that forces a second fetch, a preload with the wrong as that downloads twice, a preload competing with the largest paint. Then write the head for the clone so the same first four starts recur, keeping the hint count at or below six inside the first 20 KB of markup, and verify by re-running the capture with identical settings. Only requests the public page makes belong in the graph; anything behind a session stays unknown instead of being inferred from a hint. Rebuild stack: one preload for the hero image with imagesrcset and high fetchpriority, one modulepreload for the entry chunk, a single preconnect to the font or media origin actually used, and prefetch deferred to idle. Acceptance: the clone's first four asset starts match the reference order, no asset downloads twice, no hint targets an origin that is never requested, and the hint list ships beside the capture.
