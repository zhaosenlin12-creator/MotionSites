Fingerprint what the site persists, then separate preference writes from cache writes. Snapshot every storage surface after a clean load and again after each of six interactions: local storage, session storage, cookies including HttpOnly names, and the key list of each database. For every key record the surface, the key, the value shape as string length or JSON depth or array length, a SHA-256 over the UTF-8 value, and the step that wrote it. Record fingerprint version 2 beside each digest, because strings with unpaired UTF-16 surrogates hash over a 0xff prefix plus their exact code units, and a digest without that version cannot establish value identity at all. Mark declared secret values as redacted with a null digest and never store their bytes. Diff the two runs key by key: a key that appears only after a click and whose size tracks the interaction is state the rebuild must reproduce, while a key that changes with no interaction and looks like a cache or a nonce is noise to reproduce as structure only, with a generated value. List writes you cannot attribute, such as one set during a redirect or by a worker, as unknown instead of assigning them to the nearest step. Rebuild stack: a fingerprint table plus a small storage module writing only the state that table proves. Acceptance: every key has surface, shape, digest and writing step, version 2 appears on each digest, preferences and cache are separated by a stated rule, unattributed writes stay unknown, and no secret value is retained.
